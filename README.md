## :dart: O guia para alavancar a sua carreira

> Gulp é um task runner (automatizador de tarefas) baseado em Node.js: você descreve em JavaScript os passos do seu fluxo de trabalho — compilar Sass, minificar CSS/JS, otimizar imagens, gerar sourcemaps, recarregar o navegador — e o Gulp executa tudo em pipelines de streams. Ele foi um dos pilares da automação de front-end entre 2014 e 2019, mas hoje disputa espaço com bundlers modernos como Vite e esbuild, que resolvem boa parte do mesmo problema com configuração mínima. Ainda assim, o Gulp segue mantido (a versão 5 saiu em 2024) e continua vivo em projetos legados, temas WordPress, pipelines de design system e fluxos que precisam de controle fino sobre cada etapa da build. Este guia reúne documentação oficial, cursos, livros, ferramentas do ecossistema e um capítulo dedicado a usar IA na prática com Gulp — tudo verificado, e com honestidade sobre onde a tecnologia está hoje: não é mais o "hype", mas continua sendo conhecimento útil para quem mantém ou herda projetos que o usam.

## 🗺️ Roadmap

> O Gulp não tem um roadmap público formal como projetos maiores, mas dá pra acompanhar para onde a ferramenta está indo pelo changelog e pelos releases oficiais — inclusive a mudança mais importante dos últimos anos, o lançamento da versão 5.

- [Changelog oficial do Gulp](https://github.com/gulpjs/gulp/blob/master/CHANGELOG.md) — Histórico completo de versões. Mostra que o Gulp 5 (mar/2024) trouxe suporte a `esbuild`, `swc` e `sucrase` como loaders, export ESM e árvore de dependências mais enxuta — sinal de que o projeto segue mantido, mesmo com atividade reduzida frente aos bundlers modernos.
- [Releases do Gulp no GitHub](https://github.com/gulpjs/gulp/releases) — Todas as versões publicadas, com notas de lançamento.
- [Organização gulpjs no GitHub](https://github.com/gulpjs) — Os mais de 60 pacotes que compõem o ecossistema (vinyl, glob-watcher, gulp-cli etc.), cada um com seu próprio ritmo de manutenção.
- [roadmap.sh — Frontend Roadmap](https://roadmap.sh/frontend) — Roadmap da comunidade para front-end; hoje cita bundlers como Vite/webpack como a rota recomendada, com Gulp aparecendo como conhecimento legado útil.

## 🚀 Por onde começar

1. Confirme que você já tem [Node.js e npm instalados](https://gulpjs.com/docs/en/getting-started/quick-start/) — pré-requisito do Gulp.
2. Siga o [Quick Start oficial](https://gulpjs.com/docs/en/getting-started/quick-start/): instale o `gulp-cli` global e o `gulp` local no seu projeto.
3. Entenda [JavaScript e gulpfiles](https://gulpjs.com/docs/en/getting-started/javascript-and-gulpfiles/) — como o `gulpfile.js` (ou `.mjs`/`.cjs` no Gulp 5) organiza suas tarefas.
4. Aprenda a [criar tarefas](https://gulpjs.com/docs/en/getting-started/creating-tasks/) com `series` e `parallel`.
5. Veja como [trabalhar com arquivos](https://gulpjs.com/docs/en/getting-started/working-with-files/) usando `src()` e `dest()`, e como funcionam os [globs](https://gulpjs.com/docs/en/getting-started/explaining-globs/).
6. Instale seu primeiro plugin seguindo [Using Plugins](https://gulpjs.com/docs/en/getting-started/using-plugins/) (ex.: compilar Sass ou minificar JS).
7. Configure [observação de arquivos](https://gulpjs.com/docs/en/getting-started/watching-files/) com `watch()` para rodar tarefas automaticamente a cada alteração.
8. Antes de decidir usar Gulp em um projeto novo, compare com [Vite](https://vitejs.dev/guide/) e [esbuild](https://esbuild.github.io/getting-started/) — para a maioria dos projetos front-end modernos, eles resolvem o mesmo problema com menos configuração.

## 🛠️ Ferramentas

> Plugins essenciais do ecossistema Gulp

- [gulp-sass](https://github.com/dlmanning/gulp-sass) — Compila Sass/SCSS para CSS dentro de uma pipeline Gulp, usando o compilador oficial Dart Sass por baixo.
- [gulp-babel](https://github.com/babel/gulp-babel) — Transpila JavaScript moderno com Babel dentro do Gulp.
- [gulp-postcss](https://github.com/postcss/gulp-postcss) — Roda plugins do PostCSS (como Autoprefixer) como parte da build.
- [gulp-imagemin](https://github.com/sindresorhus/gulp-imagemin) — Otimiza imagens (PNG, JPEG, SVG, GIF) durante o build.
- [gulp-webp](https://github.com/sindresorhus/gulp-webp) — Converte imagens para o formato WebP.
- [gulp-uglify](https://github.com/terinjokes/gulp-uglify) — Minifica JavaScript (para ES5; projetos com sintaxe moderna geralmente migram para `gulp-terser`).
- [gulp-clean-css](https://github.com/scniro/gulp-clean-css) — Minifica arquivos CSS.
- [gulp-sourcemaps](https://github.com/gulp-sourcemaps/gulp-sourcemaps) — Gera sourcemaps para depurar código já processado (minificado/transpilado) no navegador.
- [gulp-concat](https://github.com/contra/gulp-concat) — Concatena múltiplos arquivos em um só.
- [gulp-rename](https://github.com/hparra/gulp-rename) — Renomeia arquivos dentro de uma pipeline (ex.: adicionar `.min` antes de salvar).
- [gulp-typescript](https://github.com/ivogabe/gulp-typescript) — Compila TypeScript dentro do Gulp.
- [gulp-htmlmin](https://github.com/jonschlinkert/gulp-htmlmin) — Minifica arquivos HTML.
- [gulp-plumber](https://github.com/floatdrop/gulp-plumber) — Evita que erros dentro de uma pipeline derrubem o processo do `watch()`.
- [gulp-notify](https://github.com/mikaelbr/gulp-notify) — Mostra notificações do sistema operacional quando uma tarefa termina ou falha.
- [gulp-changed](https://github.com/sindresorhus/gulp-changed) — Processa apenas arquivos que mudaram desde a última execução, acelerando builds incrementais.
- [gulp-if](https://github.com/robrich/gulp-if) — Executa passos condicionalmente dentro de uma pipeline (ex.: só minificar em produção).
- [gulp-connect](https://github.com/avevlad/gulp-connect) — Sobe um servidor local com live reload integrado ao Gulp.
- [gulp-livereload](https://github.com/vohof/gulp-livereload) — Recarrega o navegador automaticamente a cada mudança de arquivo.
- [del](https://github.com/sindresorhus/del) — Remove arquivos e pastas (usado nas tarefas `clean` da maioria dos gulpfiles).
- [yargs](https://github.com/yargs/yargs) — Interpreta argumentos de linha de comando, útil para gulpfiles com flags (ex.: `--production`).

> Ferramentas de apoio e do ecossistema mais amplo

- [BrowserSync](https://github.com/BrowserSync/browser-sync) — Sincroniza testes e live reload em múltiplos navegadores e dispositivos simultaneamente; muito usado junto com Gulp.
- [Autoprefixer](https://github.com/postcss/autoprefixer) — Adiciona prefixos de vendor ao CSS automaticamente, geralmente encadeado via `gulp-postcss`.
- [Terser](https://github.com/terser/terser) — Minificador de JavaScript moderno (ES6+), sucessor recomendado do UglifyJS.
- [Dart Sass](https://github.com/sass/dart-sass) — Implementação oficial e ativa do compilador Sass, usada por baixo dos panos pelo `gulp-sass`.
- [Diretório de plugins do Gulp](https://gulpjs.com/plugins/) — Busca oficial e pesquisável por qualquer plugin do ecossistema.
- [Tasks no VS Code](https://code.visualstudio.com/docs/editor/tasks) — Documentação oficial de como rodar tarefas (incluindo Gulp) direto do editor.
- [Gulp no WebStorm](https://www.jetbrains.com/help/webstorm/gulp.html) — Integração oficial da JetBrains para rodar e depurar tarefas do Gulp na IDE.

> Alternativas modernas (para comparar antes de escolher)

- [Vite](https://vitejs.dev/guide/) — Bundler e dev server modernos, hoje a escolha padrão para a maioria dos projetos novos de front-end.
- [esbuild](https://esbuild.github.io/getting-started/) — Bundler/transpilador extremamente rápido, escrito em Go; um dos motivos da queda de popularidade de task runners como o Gulp.
- [webpack](https://webpack.js.org/guides/getting-started/) — Bundler mais robusto e configurável, ainda dominante em projetos legados e corporativos.
- [Parcel](https://github.com/parcel-bundler/parcel) — Bundler com configuração zero, outra alternativa direta ao papel que o Gulp ocupava.

## 🤖 IA na prática

Gulp é um caso interessante para usar IA: a documentação é enxuta, boa parte do conhecimento está espalhado em posts de 2014–2016, e muita gente hoje só encontra um `gulpfile.js` legado sem nunca ter escrito um do zero. É exatamente aí que um assistente de IA ajuda mais.

**Para aprender**
- Cole um `gulpfile.js` legado (de um projeto WordPress, tema ou design system antigo) e peça para a IA explicar tarefa por tarefa: o que cada `.pipe()` faz e em que ordem as coisas executam.
- Peça para comparar, lado a lado, como a mesma tarefa (compilar Sass e minificar) seria escrita em Gulp, em um script npm simples e em Vite — ajuda a decidir se vale a pena migrar.
- Peça exemplos comentados de `series()` vs `parallel()` para entender quando uma tarefa depende da outra terminar antes.

**Para trabalhar**
- Use [GitHub Copilot](https://github.com/features/copilot), [Cursor](https://cursor.com/) ou [Claude Code](https://code.claude.com/docs/en/overview) para gerar rapidamente um `gulpfile.js` inicial (Sass + autoprefixer + minificação + live reload) a partir de uma descrição do que o projeto precisa.
- Peça para a IA revisar um `gulpfile` antigo (Gulp 3 ou início do Gulp 4) e apontar o que precisa mudar para rodar no [Gulp 5](https://github.com/gulpjs/gulp/blob/master/CHANGELOG.md) — a mudança mais comum é a forma como tarefas assíncronas terminam.
- Use IA para resumir os [advisories de segurança do GitHub para o ecossistema npm](https://github.com/advisories?query=gulp+ecosystem%3Anpm) relacionados a dependências transitivas de um projeto Gulp antigo — esses projetos costumam ter árvores de dependência grandes e desatualizadas.

**Limites e boas práticas**
- IA pode **inventar nomes de plugins Gulp** que não existem ou que foram descontinuados há anos (ex.: sugerir `gulp-uglify-es` para um projeto que já usa `gulp-terser`). Sempre confira o plugin no [diretório oficial](https://gulpjs.com/plugins/) antes de instalar.
- Não peça para a IA "modernizar" um `gulpfile` sem revisar: trocar `gulp-uglify` por `gulp-terser` ou atualizar globs pode mudar silenciosamente o comportamento de build em produção.
- Um `gulpfile.js` de projeto legado pode conter chaves de API, caminhos de FTP/deploy ou credenciais de ambiente coladas por descuido — nunca cole esse arquivo inteiro em uma ferramenta de IA sem revisar antes.
- A decisão de manter Gulp ou migrar para Vite/esbuild é arquitetural, não técnica: considere o tamanho da equipe, o quanto o projeto ainda vai ser mantido, e se a IA está sugerindo a migração só porque é "mais moderna".
